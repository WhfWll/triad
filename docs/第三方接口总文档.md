# 一体化安全检查平台第三方接口总文档

本文档面向第三方系统调用，覆盖以下三个模块：

1. **主机安全**
2. **应用安全**
3. **数据安全**

第三方系统统一通过 **API 秘钥** 调用，并可在任务完成后生成报告、拉取 HTML 报告内容。

---

## 1. 鉴权说明

当前第三方调用推荐使用 **平台 API 秘钥** 鉴权。

- 请求头名称：`platform-token`
- 值来源：系统配置 -> `API秘钥` 页签中生成的秘钥

示例：

```http
platform-token: 你的API秘钥
Content-Type: application/json
```

说明：

- 第三方/脚本调用时，优先使用 `platform-token`
- 用户登录态调用时，使用 `Authorization`
- 本文档中所有示例统一使用 `platform-token`

## 3. 主机安全接口

### 3.1 创建安全配置核查任务

- 方法：`POST`
- 路径：`/smart/baseline/check/batch`

请求体示例：

```json
{
  "taskId": 0,
  "targets": [
    {
      "host": "192.168.22.142",
      "port": 22,
      "username": "admin1",
      "password": "abc*123",
      "key": "",
      "osType": 1,
      "transport": 1,
      "winrmUseHttps": false,
      "scanScene": 1
    }
  ]
}
```

常用字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `host` | string | 目标主机 IP 或域名 |
| `port` | int | 连接端口 |
| `username` | string | 登录用户名 |
| `password` | string | 登录密码 |
| `key` | string | SSH 私钥内容 |
| `osType` | int | `1=Linux/Unix`，`2=Windows` |
| `transport` | int | `0=自动`，`1=SSH`，`2=WinRM` |
| `winrmUseHttps` | bool | WinRM 是否使用 HTTPS |
| `scanScene` | int | 安全配置核查固定传 `1` |

响应示例：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "taskId": 337104100
  }
}
```

### 3.2 查询任务进度

- 方法：`GET`
- 路径：`/smart/baseline/check/progress`

请求参数：

| 参数 | 类型 | 必填 | 说明 |

| `taskId` | int | 是 | 创建任务接口返回的任务 ID |

  "code": 200,

## 6. 统一报告接口

三个模块统一使用以下报告接口：

| 场景 | 方法 | 路径 |
| --- | --- | --- |
| 生成安全检查报告 | `POST` | `/smart/security/report/generate` |
| 获取报告列表 | `GET` | `/smart/security/report/list` |
| 获取报告详情（用于下载） | `GET` | `/smart/security/report/detail` |

### 6.1 生成报告

- 方法：`POST`
- 路径：`/smart/security/report/generate`

请求体示例：

#### 主机安全

```json
{
  "module": "host",
  "taskId": 337104100
}
```

#### 应用安全

```json
{
  "module": "app",
  "taskId": 420800100
}
```

#### 数据安全

```json
{
  "module": "data",
  "taskId": 530900100
}
```

响应示例：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "id": 205
  }
}
```

说明：

- 返回的 `id` 为报告 ID

### 6.2 获取报告列表

- 方法：`GET`
- 路径：`/smart/security/report/list`

请求参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | int | 是 | 页码 |
| `size` | int | 是 | 每页条数 |

### 6.3 获取报告详情并下载 HTML

- 方法：`GET`
- 路径：`/smart/security/report/detail`

请求参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | int | 是 | 报告 ID |

响应示例：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "id": 205,
    "title": "安全检查报告",
    "module": "host",
    "taskId": 337104100,
    "content": "<!DOCTYPE html><html><head>...</head><body>...</body></html>"
  }
}
```

说明：

- 当前安全检查报告**没有单独的下载流接口**
- 报告中心的真实下载方式是：读取 `content` 后，由调用方自行保存为 `.html` 文件
- 第三方系统应将 `content` 按 `text/html;charset=utf-8` 保存

5. `GET /smart/security/report/detail?id=...`

### 7.2 应用安全

2. `GET /smart/appsec/dynamic/detail?id=...`

### 7.3 数据安全

1. `POST /smart/datasec/db/run` 或 `POST /smart/datasec/sensitive/run`
2. `GET /smart/datasec/db/detail?id=...` 或 `GET /smart/datasec/sensitive/detail?id=...`
3. `POST /smart/security/report/generate`

## 8. 补充说明

### 8.1 为什么主机安全有 `progress`，而应用/数据安全没有？

因为当前系统实现中：

- 主机安全配置核查支持独立的批量任务进度接口
- 应用安全和数据安全主要通过 `detail` 接口返回当前状态和结果

### 8.2 为什么报告没有单独的 `/download` 接口？

因为当前“安全检查报告中心”的真实实现是：

- 列表：`/smart/security/report/list`
- 详情/预览：`/smart/security/report/detail`
- 下载：前端将 `detail.content` 保存为 HTML 文件

第三方若要下载报告，也应读取 `content` 后自行保存。
