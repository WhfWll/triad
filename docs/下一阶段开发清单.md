## 一、当前判断

当前项目已经完成主链路建设，三大安全模块均具备：

- 任务创建
- 任务列表
- 任务详情
- 执行日志
- 结果导出
- 报告生成 / 预览 / 下载
- 关键操作审计留痕

当前更适合进入“收口与增强”阶段，而不是继续大范围铺新页面。

---

## 二、建议优先级

### P1：规则稳定性验证与收口

这是当前最影响对外验收信心的一组工作。

1. YARA 大规则库稳定性验证
   - 验证规则重载耗时
   - 验证规则解析兼容性
   - 验证真实恶意代码检测任务命中链路
   - 输出失败规则样本与兼容性清单

2. Nuclei 模板导入与执行稳定性验证
   - 验证批量导入成功率
   - 验证模板分类、标签、严重级别映射
   - 验证执行任务是否能稳定产出结果
   - 验证导入后的规则数量口径与页面展示口径一致

**完成标志**
- YARA 规则库可稳定重载并参与扫描
- Nuclei 模板导入后可稳定用于应用安全检测
- 规则页显示数量、引擎实际加载数量、任务执行结果三者一致

### P2：数据安全规则继续补厚

这一组工作会把当前“可用”继续推向“更像成熟产品”。

1. PostgreSQL 继续补规则
   - 补充更多账号、审计、日志、网络暴露相关规则
   - 补充更细的版本与配置检查

2. Redis 继续补规则与结果表达
   - 增加高危命令、未授权访问、持久化、日志配置相关规则
   - 优化结果展示，让命中结果更清楚地表现 `db -> key -> field`

3. MongoDB / CouchDB 继续增强复杂结构识别
   - 深层数组结构识别
   - 复杂嵌套 JSON 路径识别
   - 敏感字段命中摘要优化

**完成标志**
- 五类数据库均具备“真实检查 + 敏感扫描 + 可读结果”的稳定能力
- 数据安全完成度可从约 88% 提升到 91% 以上

### P3：标准化与体验优化

这一组不是最急，但会影响最终交付观感。

1. 审计日志页面展示优化
   - 优化内容列换行
   - 优化对象摘要展示
   - 优化筛选体验

2. 导出接口标准化
   - 统一后端导出接口风格
   - 减少前端拼装型导出逻辑

3. 报告模板继续打磨
   - 继续优化长文本换行
   - 继续优化表格列宽与分页观感

**完成标志**
- 页面查阅与导出体验更统一
- 交付展示效果更稳定

---

## 三、推荐执行顺序

建议按下面顺序推进：

1. **YARA / Nuclei 稳定性验证**
2. **数据安全规则继续补厚**
3. **导出与审计日志展示标准化**

原因很简单：

- 第一阶段解决“能不能稳定跑”
- 第二阶段解决“能力够不够厚”
- 第三阶段解决“展示够不够完整”
