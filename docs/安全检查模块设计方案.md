## 二、三大安全引擎模块

### 模块 1：主机安全引擎（Host Security Engine）

#### 1.1 安全配置核查子模块

**功能**：登录目标主机，采集系统配置，对比安全基线，生成合规评分。

```
输入：目标IP + 凭据（密码/密钥）+ OS类型
流程：
  1. 建立SSH/WinRM连接
  2. 根据OS类型加载对应基线规则集
  3. 逐条执行采集命令（如：uname -r、iptables -L、cat /etc/passwd...）
  4. 比对命令输出与基线期望值
  5. 生成通过/不通过结果 + 风险等级 + 修复建议
输出：配置核查报告
```

**支持OS**：
| 系统 | 连接方式 | 说明 |
|---|---|---|
| Linux/Unix | SSH | 全量基线规则（~1000条） |
| Windows | WinRM | PowerShell采集（~300条） |
| 国产OS（Kylin/UOS） | SSH | 共享Linux规则80% + 特有适配 |
| 嵌入式OS | SSH/Telnet | 精简规则集（~100条） |

**基线规则分类**：
- 密码策略（复杂度、过期时间、锁定阈值）
- 用户权限（root登录限制、空密码账户、sudo配置）
- 防火墙规则（iptables/nftables状态、默认策略、开放端口）
- 内核安全（sysctl参数、ASLR、SELinux/AppArmor状态）
- 文件权限（关键系统文件权限、umask）
- 审计日志（auditd状态、日志大小、留存周期）
- 网络服务（不必要的服务、监听端口、SSH配置）
- 系统更新（补丁状态、软件源配置）

#### 1.2 漏洞扫描子模块（白盒增强）

**功能**：登录后获取系统精确信息，匹配漏洞库。

```
流程：
  1. 建立SSH/WinRM连接
  2. 执行 uname -r、rpm -qa/dpkg -l 获取精确版本
  3. 与vul_libraries漏洞库做版本匹配
  4. 发现关联CVE/漏洞
输出：漏洞列表（含精准版本证据）
```

#### 1.3 恶意代码检测子模块

**功能**：扫描目标主机文件系统、进程、网络连接，发现恶意痕迹。

```
检测项：
  ├─ 文件完整性检查：对比关键系统文件hash（/bin/ls、/bin/ps、/sbin/ifconfig...）
  ├─ 进程异常检测：隐藏进程、可疑进程名、高CPU/内存进程
  ├─ 网络连接检测：异常外连IP/端口、反向连接
  ├─ Webshell检测：web目录下可疑脚本文件（一句话木马、加密代码）
  ├─ Rootkit检测：内核模块检查、LD_PRELOAD检查、/proc异常
  └─ 敏感文件扫描：临时目录异常文件、可疑定时任务
```

### 模块 2：应用安全引擎（Web Application Security Engine）

#### 功能说明

**核心能力**：在应用程序运行状态下，对其进行动态安全测试，模拟真实攻击。

**已具备的底层能力**（项目中已有）：
- MITM代理扫描
- CrawlerX无头浏览器爬虫
- 通用PoC引擎
- AI增强扫描

#### 2.1 专项应用检测子模块

**功能**：针对15种应用类型加载专项PoC规则。

```
支持应用列表（需求要求15种）：
  万户、用友、蓝凌、云时空、亿赛通、D-Link、通达...
  + 其他CMS/框架（WordPress、ThinkPHP、Spring Boot等）

规则来源：Nuclei-Templates + 公开PoC库
规则数量：7000+（包含远程代码执行、未授权访问、SQL注入、文件上传、弱口令等）
```

#### 2.2 动态扫描子模块

**功能**：爬虫 + 实时流量分析 + 漏洞验证。

```
流程：
  1. CrawlerX爬取应用页面，构建站点地图
  2. 记录所有请求/响应流量
  3. MITM代理实时检测请求中的漏洞特征
  4. 对发现的疑似漏洞发送PoC验证
输出：漏洞详情（含请求报文、响应证据）
```

### 模块 3：数据安全引擎（Data Security Engine）

#### 3.1 数据库连接管理器

**功能**：统一管理5种数据库的连接。

| 数据库 | 连接方式 | Go驱动 |
|---|---|---|
| MySQL | 原生TCP协议 | `github.com/go-sql-driver/mysql` |
| PostgreSQL | 原生协议 | `github.com/jackc/pgx/v5` |
| MongoDB | BSON协议 | `go.mongodb.org/mongo-driver` |
| Redis | RESP协议 | `github.com/redis/go-redis/v9` |
| CouchDB | HTTP REST API | `net/http` 直接调用 |

**能力**：
- 连接池管理（按库类型分组）
- 连接超时/心跳/重试
- 支持凭据认证
- 并发控制（需求要求并发5个）

#### 3.2 数据库漏洞扫描子模块

**功能**：检测数据库已知漏洞。

```
检测方式：
  ├─ 版本比对：查询版本号（SELECT version()）→ 匹配CVE
  ├─ PoC验证：对部分漏洞发送验证载荷
  └─ 配置检测：检查配置参数是否存在安全风险

规则来源：CIS Database Benchmark + 公开数据库PoC
规则数量：约2000条
```

#### 3.3 数据库配置核查子模块

**功能**：登录数据库检查安全配置项。

| 检查维度 | MySQL | PostgreSQL | MongoDB | Redis | CouchDB |
|---|---|---|---|---|---|
| 身份认证 | auth方式、密码强度 | pg_hba.conf、密码加密 | auth enabled、x.509 | requirepass | admin密码 |
| 权限控制 | 用户权限、匿名账户 | 角色管理、public权限 | 角色、白名单 | rename command、ACL | 用户权限 |
| 配置安全 | 端口、local-infile、log | 端口、SSL、log | 端口、SSL、审计 | 绑定地址、保护模式 | CORS、SSL |
| 审计日志 | general log、audit plugin | log_statement、audit | audit log | slow log | 审计功能 |

**规则数量**：每种DB约200条，共约1000条

#### 3.4 敏感数据发现子模块

**功能**：遍历数据库表/字段，发现并分类敏感数据。

```
流程：
  1. 连接目标数据库
  2. 扫描所有库/表/字段元信息
  3. 根据字段名匹配（如：id_card、phone、bank_account...）
  4. 采样数据内容进行正则匹配
  5. 标记敏感字段并分级（高/中/低）
输出：敏感数据分布清单

敏感数据分类（约800条规则）：
  ├─ 高敏：身份证号、银行卡号、护照号、信用卡CVV
  ├─ 中敏：手机号、邮箱、家庭地址、出生日期
  ├─ 低敏：姓名、性别、城市
  └─ 其他：Token、密钥、证书、密码hash
```

## 三、通用基础设施模块

### 模块 4：连接管理层

**功能**：统一管理所有到目标主机的连接，供三大引擎共享。

```
HostConnManager
├── SSH连接池（Linux/国产OS/嵌入式OS）
│   ├── 基于 golang.org/x/crypto/ssh
│   ├── 支持密码/密钥认证
│   ├── 命令执行 + 文件传输（SFTP）
│   └── 会话复用/超时断开
├── WinRM连接池（Windows）
│   ├── 基于 github.com/masterzen/winrm
│   ├── 支持用户名密码/Kerberos
│   ├── PowerShell命令执行
│   └── 会话复用
└── Telnet连接池（嵌入式OS）
    ├── 基于 net/textproto
    └── 简单命令交互
```

> **现有基础**：项目中 `services/post_exploitation/yak.go` 已有SSH通道能力，需提取为公共模块。

### 模块 5：规则引擎层

**功能**：统一管理所有检测规则。

```
RuleEngine
├── 主机基线规则库
│   ├── 按OS分类（Linux/Win/国产OS/嵌入式）
│   └── 每条规则：命令 + 期望值 + 风险等级 + 修复建议
├── 应用PoC规则库（7000+）
│   ├── 按应用分类（万户/用友/蓝凌等）
│   └── 格式兼容 Yak / Nuclei 脚本
├── 数据库基线规则库（1000+）
│   ├── 按DB分类（MySQL/PG/Mongo/Redis/CouchDB）
│   └── 每条规则：检查SQL + 期望值 + 风险等级
├── 敏感数据规则库（800+）
│   ├── 正则规则（匹配数据内容）
│   └── 字段名规则（匹配字段名）
└── 恶意代码特征库（200+）
    ├── 文件hash签名
    ├── Webshell关键词
    └── 进程白名单
```

### 模块 6：任务调度与并发控制

**功能**：调度三大引擎的执行。

```
TaskScheduler
├── 任务队列（按优先级/创建时间）
├── 并发控制：主机10个 / 应用5个 / 数据5个
├── 目标分配：均衡分配到各引擎
├── 状态管理：等待→运行→完成→失败
├── 超时控制：任务级/目标级超时
└── 熔断机制：失败阈值触发暂停
```

> **现有基础**：项目中 `crons/targetcreate.go` 已有 `MaxRunningTaskNumber/MaxRunningTargetNumber` 控制，直接扩展。

### 模块 7：结果管理

**功能**：统一存储和查询三种扫描结果。

```
ResultManager
├── 配置核查结果
│   ├── 每条检测项：通过/不通过/错误
│   ├── 原始命令输出（证据）
│   └── 风险评分
├── 漏洞扫描结果
│   └── 已有 task_vul 表，复用
├── 恶意代码检测结果
│   ├── 文件路径 + 匹配规则 + 风险等级
│   └── 进程PID + 可疑行为描述
├── 敏感数据发现结果
│   ├── 数据库名/表名/字段名
│   ├── 敏感数据类型 + 级别
│   └── 采样数据（脱敏）
└── 分类聚合
    ├── 按检测项分类
    ├── 按风险等级聚合
    └── 按目标主机聚合
```

### 模块 8：报告与导出

**功能**：生成包含三类检测结果的完整报告。

```
报告包含：
├── 总体安全评分
├── 主机安全
│   ├── 配置核查通过率
│   ├── 漏洞统计
│   └── 恶意代码检查结果
├── 应用安全
│   ├── 漏洞统计 + 风险分布
│   └── PoC检测详情
├── 数据安全
│   ├── 数据库配置合规率
│   ├── 漏洞统计
│   └── 敏感数据分布
└── 修复建议汇总

导出格式：PDF / Excel / HTML
```

> **现有基础**：项目已有报表系统 `services/report.go`，扩展模板即可。

### 模块 9：用户管理与审计日志

**功能**：用户权限控制 + 操作行为记录。

**现有基础**：项目中 `services/user.go` + `services/logAudit.go` 已完善，直接复用。

## 四、模块依赖关系

```
模块6（任务调度）                   ← 入口
  ├─→ 模块4（连接管理）             ← 建立连接
  │     ├─→ 模块1（主机安全引擎）    ← 执行主机扫描
  │     │     ├─→ 模块5（规则引擎）   ← 获取基线规则
  │     │     └─→ 模块7（结果管理）   ← 存储结果
  │     ├─→ 模块2（应用安全引擎）    ← 执行应用扫描
  │     │     ├─→ 模块5（规则引擎）   ← 获取PoC规则
  │     │     └─→ 模块7（结果管理）   ← 存储结果
  │     └─→ 模块3（数据安全引擎）    ← 执行数据扫描
  │           ├─→ 模块5（规则引擎）   ← 获取DB基线 + 敏感数据规则
  │           └─→ 模块7（结果管理）   ← 存储结果
  └─→ 模块8（报告导出）             ← 生成报告

模块9（用户/审计）                   ← 全程辅助
```

## 五、开发优先级建议

| 优先级 | 模块 | 原因 |
|---|---|---|
| P0 | 模块4 连接管理（SSH优先） | 所有登录式扫描的前置条件 |
| P0 | 模块5 规则引擎 + 规则库导入 | 规则是检测的核心 |
| P0 | 模块1 主机安全引擎 | 需求最重要部分 |
| P1 | 模块3 数据安全引擎 | 需求第二重要 |
| P1 | 模块6 任务调度扩展 | 控制执行 |
| P1 | 模块7 结果管理扩展 | 存储结果 |
| P2 | 模块2 应用安全引擎（规则补充） | 已有基础，补齐就行 |
| P2 | 模块8 报告导出扩展 | 已有基础 |
| P3 | 模块4 WinRM/Telnet | 后补 |
