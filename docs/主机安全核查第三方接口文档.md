# 主机安全核查第三方接口文档

本文档面向第三方系统调用，聚焦“一体化安全检查平台”中的 **主机安全 -> 安全配置核查** 能力。

推荐第三方系统按以下 5 个接口完成完整闭环：

1. 创建核查任务
2. 查询任务进度
3. 获取最终核查结果
4. 生成主机安全核查报告
5. 获取报告详情并下载 HTML 报告

---

## 1. 鉴权说明

当前第三方调用推荐使用 **平台 API 秘钥** 鉴权。

- 请求头名称：`platform-token`
- 值来源：系统配置 -> `API秘钥` 页签中生成的秘钥

示例：

```http
platform-token: 你的API秘钥
Content-Type: application/json
```

说明：

- 第三方/脚本调用时，优先使用 `platform-token`
- 用户登录态调用时，使用 `Authorization`
- 本文档中的第三方调用示例，统一使用 `platform-token`

---

## 2. 接口总览

| 场景 | 方法 | 路径 |
| --- | --- | --- |
| 创建安全配置核查任务 | `POST` | `/smart/baseline/check/batch` |
| 查询任务进度 | `GET` | `/smart/baseline/check/progress` |
| 获取核查结果列表 | `GET` | `/smart/baseline/result` |
| 生成安全检查报告 | `POST` | `/smart/security/report/generate` |
| 获取报告列表 | `GET` | `/smart/security/report/list` |
| 获取报告详情（用于预览/下载） | `GET` | `/smart/security/report/detail` |

说明：

- 即使只有 1 台主机，也推荐统一走批量接口 `/smart/baseline/check/batch`
- 安全检查报告当前**没有独立的后端下载流接口**
- 报告中心下载逻辑实际为：`查询报告详情 -> 取 content HTML -> 第三方自行保存为 .html 文件`

## 3. 创建核查任务

### 3.1 请求信息

- 方法：`POST`
- 路径：`/smart/baseline/check/batch`
- Content-Type：`application/json`

### 3.2 请求头

```http
platform-token: 你的API秘钥
Content-Type: application/json
```

### 3.3 请求体

```json
{
  "taskId": 0,
  "targets": [
    {
      "host": "192.168.22.142",
      "port": 22,
      "username": "admin1",
      "password": "abc*123",
      "key": "",
      "osType": 1,
      "transport": 1,
      "winrmUseHttps": false,
      "scanScene": 1
    }
  ]
}
```

### 3.4 字段说明

#### 顶层字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `taskId` | int | 否 | 任务批次号。传 `0` 或不传时，由服务端自动生成 |
| `targets` | array | 是 | 目标主机列表，至少 1 个 |

#### `targets[]` 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `host` | string | 是 | 目标主机 IP 或域名 |
| `port` | int | 否 | 连接端口。SSH 默认 `22`，WinRM HTTP 默认 `5985`，WinRM HTTPS 默认 `5986` |
| `username` | string | 是 | 登录用户名 |
| `password` | string | 否 | 登录密码 |
| `key` | string | 否 | SSH 私钥内容，WinRM 场景通常留空 |
| `osType` | int | 是 | 操作系统类型 |
| `transport` | int | 否 | 连接方式：`0=自动`，`1=SSH`，`2=WinRM` |
| `winrmUseHttps` | bool | 否 | WinRM 是否使用 HTTPS，`true=5986`，`false=5985` |
| `scanScene` | int | 否 | 扫描场景。安全配置核查固定传 `1` |

### 3.5 `osType` 建议值

| 值 | 说明 |
| --- | --- |
| `1` | Linux/Unix |
| `2` | Windows |

### 3.6 成功响应示例

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "taskId": 337104100
  }
}
```

### 3.7 curl 示例

```bash
curl -X POST "http://127.0.0.1:8101/smart/baseline/check/batch" ^
  -H "platform-token: 你的API秘钥" ^
  -H "Content-Type: application/json" ^
  -d "{\"taskId\":0,\"targets\":[{\"host\":\"192.168.22.142\",\"port\":22,\"username\":\"admin1\",\"password\":\"abc*123\",\"key\":\"\",\"osType\":1,\"transport\":1,\"winrmUseHttps\":false,\"scanScene\":1}]}"
```

## 4. 查询任务进度

### 4.1 请求信息

- 方法：`GET`
- 路径：`/smart/baseline/check/progress`

### 4.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `taskId` | int | 是 | 创建任务接口返回的任务 ID |

### 4.3 成功响应示例

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "taskId": 337104100,
    "status": "running",
    "totalTargets": 1,
    "completedTargets": 0,
    "createdAt": "2026-06-08 15:04:28",
    "targets": [
      {
        "host": "192.168.22.142",
        "status": "running",
        "message": "已检查 186/1183 项",
        "totalItems": 1183,
        "items": [
          {
            "ruleId": 512,
            "ruleName": "检查 SSH MAC 配置",
            "checkResult": 2,
            "resultName": "不通过",
            "expectedValue": "hmac-sha2-512",
            "actualValue": "NOT_FOUND",
            "time": "2026-06-08 15:04:34"
          }
        ]
      }
    ]
  }
}
```

### 4.4 轮询建议

- 轮询间隔：`2 ~ 5 秒`
- 当 `status=completed` 时停止轮询
- 当所有目标都为 `completed` 或 `failed` 时，也可视为任务结束

## 5. 获取最终核查结果

该接口用于任务完成后，分页获取最终落库的核查结果明细。

### 5.1 请求信息

- 方法：`GET`
- 路径：`/smart/baseline/result`

### 5.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `taskId` | int | 是 | 任务 ID |
| `targetId` | int | 否 | 目标 ID，单目标场景可不传 |
| `page` | int | 否 | 页码，默认 `1` |
| `size` | int | 否 | 每页数量，默认 `10` |

### 5.3 成功响应示例

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "list": [
      {
        "id": 95231,
        "taskId": 337104100,
        "targetId": 1,
        "targetIp": "192.168.22.142",
        "ruleId": 512,
        "ruleName": "检查 SSH MAC 配置",
        "categoryName": "SSH配置",
        "riskLevel": 2,
        "checkResult": 2,
        "resultName": "不通过",
        "expectedValue": "hmac-sha2-512",
        "actualValue": "NOT_FOUND",
        "repairSuggestion": "请修改 SSH MAC 配置，确保符合安全要求",
        "checkTime": "2026-06-08 15:04:34"
      }
    ],
    "page": 1,
    "size": 200,
    "total": 1183
  }
}
```

### 5.4 使用建议

- `progress` 接口适合做运行中轮询
- `result` 接口适合做任务完成后的归档、同步、报表展示

## 6. 生成主机安全核查报告

该接口用于基于主机安全核查任务生成一份 HTML 报告，并保存到“报告中心”。

### 6.1 请求信息

- 方法：`POST`
- 路径：`/smart/security/report/generate`
- Content-Type：`application/json`

### 6.2 请求头

```http
platform-token: 你的API秘钥
Content-Type: application/json
```

### 6.3 请求体

```json
{
  "module": "host",
  "taskId": 337104100
}
```

### 6.4 字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `module` | string | 是 | 报告模块。主机安全核查固定传 `host` |
| `taskId` | int | 是 | 主机安全核查任务 ID |

### 6.5 成功响应示例

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "id": 128
  }
}
```

说明：

- 返回的 `id` 为安全检查报告 ID
- 后续可使用该 `id` 查询报告详情或下载报告内容

### 6.6 curl 示例

```bash
curl -X POST "http://127.0.0.1:8101/smart/security/report/generate" ^
  -H "platform-token: 你的API秘钥" ^
  -H "Content-Type: application/json" ^
  -d "{\"module\":\"host\",\"taskId\":337104100}"
```

## 8. 获取报告详情并下载 HTML

当前安全检查报告**没有单独的后端下载流接口**。  
报告中心页面的下载逻辑是：

1. 调用 `/smart/security/report/detail?id=报告ID`
2. 读取返回体中的 `content`
3. 将 `content` 按 `text/html` 保存为 `.html` 文件

因此第三方系统若要“下载报告”，应走本接口。

### 8.1 请求信息

- 方法：`GET`
- 路径：`/smart/security/report/detail`

### 8.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | int | 是 | 报告 ID |

### 8.3 成功响应示例

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "id": 128,
    "title": "主机安全检查报告 #337104100",
    "module": "host",
    "taskId": 337104100,
    "content": "<!DOCTYPE html><html><head>...</head><body>...</body></html>"
  }
}
```

### 8.4 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | int | 报告 ID |
| `title` | string | 报告标题 |
| `module` | string | 所属模块 |
| `taskId` | int | 关联任务 ID |
| `content` | string | 报告 HTML 全量内容 |

### 8.5 第三方下载建议

第三方系统拿到 `content` 后，可直接：

- 以 `text/html;charset=utf-8` 保存为本地文件
- 文件名建议使用：`${title}.html`

### 8.6 curl 示例

```bash
curl -X GET "http://127.0.0.1:8101/smart/security/report/detail?id=128" ^
  -H "platform-token: 你的API秘钥"
```

## 9. 对接流程示例

推荐第三方系统按以下顺序调用：

### 步骤 1：创建任务

```http
POST /smart/baseline/check/batch
```

### 步骤 2：轮询任务进度

```http
GET /smart/baseline/check/progress?taskId=337104100
```

### 步骤 3：拉取最终核查结果

```http
GET /smart/baseline/result?taskId=337104100&page=1&size=200
```

### 步骤 4：生成报告

```http
POST /smart/security/report/generate
```

请求体：

```json
{
  "module": "host",
  "taskId": 337104100
}
```

### 步骤 5：获取报告详情并下载

```http
GET /smart/security/report/detail?id=128
```

第三方将返回的 `content` 另存为 HTML 文件即可。

## 10. 常见问题

### 10.1 为什么第三方调用不用 `Authorization`？

因为当前系统中：

- `Authorization`：主要给登录用户态使用
- `platform-token`：主要给第三方平台、脚本、外部系统调用使用

### 10.2 `progress` 和 `result` 接口有什么区别？

- `progress`：返回运行中的阶段性进度，适合轮询
- `result`：返回任务完成后最终落库结果，适合归档和正式展示

### 10.3 为什么报告下载没有单独 `/download` 接口？

因为当前“安全检查报告中心”的真实实现是：

- 列表：`/smart/security/report/list`
- 详情/预览：`/smart/security/report/detail`
- 下载：前端将 `detail.content` 保存为 HTML 文件

所以第三方若要下载报告，也应读取 `content` 后自行保存。
