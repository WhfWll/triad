> 对照文档：`docs/需求.md`  
> 分析基准：当前代码库（Triad / SecGuard）+ 开发环境 MySQL（`config.json` → `triad`）  
> 更新日期：2026-05-23（修订：补充 `data/baseline/` 与库内实测数据）

## 一、总体结论

| 模块 | 整体完成度 | 可演示程度 | 验收风险 |
|------|-----------|-----------|---------|
| **1. 主机安全检查** | 约 **80%** | 高 — 三类扫描 + 4400+ 规则已入库 | 缺结果导出与操作审计 |
| **2. 应用安全检查** | 约 **55%** | 中 — DAST 全流程可用 | **7000+ 规则未达标**（库内约 1092）；15 应用类型、分类管理不足 |
| **3. 数据安全检查** | 约 **75%** | 中 — MySQL 完整 + 3800+ 规则已入库 | PG/Mongo 等执行深度不足；CVE SQLite 需 CGO |

### 1.1 当前环境数据实测（MySQL `triad`）

| 数据项 | 需求指标 | 仓库源文件 | 库内实测 | 是否达标 |
|--------|---------|-----------|---------|---------|
| 主机基线规则 | **1200+** | `data/baseline/compliance_rules.json` **4526 条** | `host_baseline_rule` **4433 条 enabled** | ✅ |
| 数据安全规则 | **3800+** | 内置 32 + `data/default-cve.db` CVE 导入 | `datasec_rule` **3832 条 enabled** | ✅ |
| 应用 PoC 规则 | **7000+** | 依赖运维导入漏洞包 | `vul_libraries` **1092 条** | ❌ |

> **说明**：规则类数据采用「**仓库 JSON/SQLite 源文件 → 导入 MySQL → 运行时从库加载**」两层结构。  
> 上表「库内实测」为当前开发库快照；**新环境部署**仍需按 §十 执行导入，否则规则数为 0。

**跨模块共性：**

- **历史记录**：三类基本具备（任务列表 + 详情 + 执行日志）。
- **用户管理**：复用平台能力（用户管理页 + 任务按 `user_id` 隔离）。
- **结果导出 / 审计日志**：应用安全最好（CSV + TXT）；主机、数据安全明显落后。

### 2.2 规则数据说明（`data/baseline/`）

**是的，1200+ 条主机检测规则就是 `data/baseline/` 目录下的 JSON 文件**，主文件为 `compliance_rules.json`。

| 文件 | 规则数 | 用途 |
|------|--------|------|
| `compliance_rules.json` | **4526** | 主规则包（英/混合） |
| `compliance_rules_zh.json` | 4526 | 中文版（结构同上） |
| `compliance_rules_linux.json` | 1751 | Linux 子集 |
| `custom_rules.json` | 5 | 自定义补充 |

**按 OS 分布（`compliance_rules.json`）：**

| osType | OS | 规则数 |
|--------|-----|--------|
| 1 | Linux/Unix | 1751 |
| 2 | Windows | 51 |
| 3 | 国产 OS | 1751 |
| 4 | 嵌入式 OS | 973 |

**加载链路（两层结构）：**

```
data/baseline/*.json          ← 项目自带规则源（安装包）
        │
        │  POST /smart/baseline/rules/import（或历史初始化脚本）
        ▼
MySQL host_baseline_rule      ← 运行时权威存储（当前 4433 条）
        │
        │  smart.go → InitBaselineRulesFromDB（启动时只读 DB，不读 JSON）
        ▼
BaselineEngine 内存           ← 扫描实际使用的规则
```

> 注意：`smart.go` 注释写明「**不再从 JSON 文件加载**」。`BaselineEngine.Init()` 虽能读 `data/baseline/`，但启动流程**未调用**。  
> 因此：**文件在仓库 ≠ 自动生效**，必须导入 MySQL；**当前开发库已完成导入**。

**Go 代码内置兜底规则（88 条）**：`services/baseline_rule.go` 的 `init()` 会加载；但若 DB 有 enabled 行则以 DB 为准，DB 为空时会被清空。

### 2.3 前端入口

| 路由 | 页面 | 功能 |
|------|------|------|
| `/hostsec/tasks` | `HostSecurityHub.vue` | 任务中心（基线 / CVE / YARA） |
| `/hostsec/task-detail` | `HostTaskDetail.vue` | 任务详情 |
| `/hostsec/rules` | `HostDetectionRules.vue` | 基线规则管理（读 `host_baseline_rule`） |
| `/hostsec/vuln-rules` | `VulnDetectionRules.vue` | CVE 库浏览 |
| `/hostsec/malware-rules` | `MalwareDetectionRules.vue` | 恶意代码规则 |
| `/hostbaseline` | `HostBaselineAudit.vue` | 旧版基线页（含 Auto/SSH/WinRM） |

### 2.4 主要缺口

1. **新环境部署** — 无「一键同步内置规则」API（对比数据安全 `import-builtin`）；需手动 JSON 导入或 SQL 初始化。
2. **结果导出** — 任务详情无 CSV/摘要下载。
3. **操作审计** — baseline / malware / vulnscan API 写入 `log_audit`。
4. **文案** — `HostBaselineAudit.vue` 仍写「引擎加载 data/baseline JSON」，与当前 DB 加载逻辑不一致。

### 4.1 需求对照表

| # | 需求项 | 状态 | 说明 |

| 2 | 并发扫描 **5** 个 | ✅ 已实现 | `dataSecMaxConcurrentDB = 5` |
| 3 | 支持 **5 种**数据库 | ⚠️ 部分 | UI/API 五种都有；**执行深度差异大**（见 4.2） |
| 4 | 内置规则 **3800+** 条 | ✅ **已达标（当前环境）** | 库内 `datasec_rule` **3832 条 enabled** |
| 5 | 分类管理 | ⚠️ 部分 | 8 类规则 + 敏感类型；`DataDetectionRules.vue` 可 CRUD |
| 6 | 审查结果导出 | ⚠️ 部分 | 目标库 JSON 导出 ✅；**扫描结果无 CSV/报告** |

| 8 | 用户管理 | ✅ 平台级 | 任务按用户隔离 |
| 9 | 历史记录查看 | ✅ 已实现 | 列表 / 详情 / 再次检测 / 删除 / 克隆目标 |

### 4.2 五种数据库实际能力

| 数据库 | dbType | 连接 | 基线规则 | 敏感发现 | CVE 版本匹配 |
|--------|--------|------|----------|----------|-------------|
| MySQL | 1 | ✅ 完整 SQL | 16 条可执行 | ✅ 完整 | ✅ |
| PostgreSQL | 2 | ⚠️ TCP 探测 | 5 条（**缺 lib/pq，SQL 未执行**） | ❌ | ⚠️ |
| MongoDB | 3 | ⚠️ HTTP 探测 | 3 条（**占位，常直接通过**） | ❌ | ⚠️ |
| Redis | 4 | ✅ go-redis | 5 条 CONFIG | ❌ | ✅ |
| CouchDB | 5 | ⚠️ HTTP | 3 条（占位） | ❌ | ⚠️ |

### 4.3 规则数量说明

| 来源 | 数量 | 说明 |
|------|------|------|
| Go 内置可执行规则 | **32 条** | MySQL 16 + PG 5 + Mongo 3 + Redis 5 + Couch 3 |
| 当前库内规则 | **3832 条 enabled** | `datasec_rule` 表（含 CVE 导入的知识库条目） |
| CVE 库源文件 | `data/default-cve.db`（约 1.2GB） | SQLite；本机可匹配约 1.7 万+ 数据库相关 CVE |
| CVE 导入规则类型 | 知识库 `cve_kb` | **不执行 SQL**；扫描时靠在线 CPE 版本匹配 |
| 扫描时 CVE 匹配 | 最多查 800 / 展示 50 | `db_baseline_cve.go` |

**存储分工：**

| 数据 | 存储 | 说明 |
|------|------|------|
| 检测规则（业务） | MySQL `triad.datasec_rule` | 页面 CRUD、同步内置、JSON/CVE 导入 |
| CVE 知识库（来源） | 本地 SQLite `data/default-cve.db` | CVE 预览/导入与扫描时版本匹配 |
| 扫描结果 | MySQL `db_check_result` / `sensitive_data_result` | 基线、CVE、敏感字段 |

**说明**：3832 条已入库时，「从 CVE 库导入」按钮灰掉**不影响**规则数量达标；按钮依赖运行时能否打开 SQLite（CGO + 重启）。

**CVE 导入按钮不可用常见原因：**

1. `default-cve.db` 不存在或未放在 `data/` 目录。
2. 后端启动后才放置文件 — 需**重启**（`GetCveDB` 仅初始化一次）。
3. Windows 编译未启用 **CGO** — `go-sqlite3` 无法打开 SQLite（需 `CGO_ENABLED=1` 重新编译）。

### 4.4 前端入口

| 路由 | 页面 | 功能 |
|------|------|------|
| `/datasec/tasks` | `DataSecTaskHub.vue` / `DBSecurity.vue` | 数据库检查任务（可勾选敏感扫描） |
| `/datasec/task/detail` | `DataSecTaskDetail.vue` | 详情（基线 / CVE / 敏感 / 日志） |
| `/datasec/rules` | `DataDetectionRules.vue` | 检测规则 + CVE 导入 |
| `/datasec/targets` | `DataSecTargetLibrary.vue` | 数据库目标库 |

### 4.5 主要缺口

1. **新环境部署** — 需同步内置 32 条 + CVE 导入（或 SQL 初始化）才能达到 3800+。
2. **PostgreSQL** — 接入 `lib/pq`，实现真实 SQL 基线与敏感扫描。
3. **MongoDB / CouchDB** — 基线从占位改为真实检查。
4. **扫描结果导出** — 对标 `AppSecTaskDetail` 的 CSV/TXT。
5. **非 MySQL 敏感发现** — 至少扩展到 PostgreSQL。
